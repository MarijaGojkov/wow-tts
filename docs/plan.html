Goal

What finished looks like

One command reads the quest file and produces every audio file:

dotnet run --project WowQuestTts -- --input data/quests.json --limit 50
  • Estimates the cost before spending anything.
  • Creates output/<questId>-accept.mp3, -progress.mp3 and -complete.mp3 for each quest.
  • Skips files that already exist, so an interrupted run continues where it stopped.
  • Lists any quests that failed, so you can retry just those.

How it works

From quest text to audio

  1. LoadReads the quest file into quest objectsQuestLoader
  2. Clean textReplaces $N, $B, $G with words or pausesTextCleaner
  3. Pick voiceQuest giver's race and gender → voiceVoicePicker
  4. Build SSMLText, voice, pauses and speaking styleSsmlBuilder
  5. Azure SpeechSends SSML, gets audio, retries when throttledSpeechGenerator
  6. Save and reportWrites files, skips done ones, logs failuresBatchRunner

Structure

Project layout after Phase 6

Files are only added in the phase that needs them, so the project starts as a single Program.cs.

wow-tts/
├─ WowQuestTts/
│  ├─ Program.cs            entry point: reads options, starts the run
│  ├─ Options.cs            command-line options
│  ├─ Models/Quest.cs       the quest data model
│  ├─ QuestLoader.cs        reads the quest JSON file
│  ├─ TextCleaner.cs        replaces $N, $B, $G and other placeholders
│  ├─ VoicePicker.cs        race + gender → voice name
│  ├─ SsmlBuilder.cs        builds the SSML for one text
│  ├─ SpeechGenerator.cs    calls Azure Speech, retries on throttling
│  └─ BatchRunner.cs        loops over quests, skips done files, reports
├─ WowQuestTts.Tests/       unit tests for cleaner, voice picker and SSML
├─ data/
│  ├─ sample-quests.json    5 test quests
│  └─ settings.json         voices, player profile, audio format, price
├─ output/                  generated audio (git-ignored)
├─ PLAN.md
└─ README.md

Phase 5A voice for every NPC

Planned

Quest givers of different races and genders sound different.

Objectives

  • Add SsmlBuilder:

  • Add tests for the voice picker fallback and SSML escaping.

Phase 6Ready for thousands

Planned

The app runs for hours, survives interruptions and tells you the cost up front.

Objectives

  • Command-line options: --input, --output, --limit N, --only <questId>, --dry-run, --force, --list-voices.
  • Skip files that already exist, unless --force is given.
  • Retry throttled requests (HTTP 429) and temporary errors with growing waits. After a few failed tries, log the failure and move on.
  • Send one request at a time first. Add a few parallel requests only if it's too slow.
  • Show a progress line for each file, e.g. [120/4000] 783-accept.mp3.
  • --dry-run counts characters and estimates the cost from the price in settings, without calling Azure.
  • Print created, skipped and failed counts at the end. Write failures to output/failed.json.

Complete when

A run you stop halfway continues where it stopped, and the dry run prints a character count and cost estimate.

Watch out for

Risks

RiskHow we handle it
The full run costs more than expectedDry-run estimate, --limit, one zone first, budget alert
Azure throttles requests (HTTP 429)Retry with growing waits, few parallel requests
HD voices aren't offered in East USCheck in Phase 3. If needed, add a Speech resource in another region
Placeholders get read aloud ("dollar N")TextCleaner with tests, and the Phase 7 data check flags leftovers
& or < in quest text breaks the SSMLEscape all text, with a test for it
Quest text and audio belong to BlizzardPrivate repo, real data exports git-ignored, audio never published
The Speech key leaksKey only in environment variables, never in a file

Not in this plan
