Goal

What finished looks like

  • POST /api/speech turns any text into an MP3.
  • GET /api/quests lists the quests, and GET /api/quests/{id} shows one.
  • GET /api/quests/783/audio/accept generates a quest's audio once and saves it, so Azure is only paid once per text.
  • The audio is saved straight into the addon's folder. Open the quest in game and the addon plays it.

API and addon

How they work together

The addon never calls the API.

WoW's Lua has no network access: no HTTP, no sockets. An addon can only play sound files that are already in its own folder. So the API writes the files, and the addon plays them.

Before playing

Web API

  1. You call the API from Scalar or the .http file
  2. The API asks Azure Speech for the audio
  3. It saves the MP3 in the addon's audio folder
→ AddOns\WowTts\audio\
783-accept.mp3 →

In game

WowTts addon

  1. A quest window opens
  2. The addon takes the quest ID
  3. PlaySoundFile plays the matching MP3. No file means no sound

WoW only finds files that existed when the game started. After generating new audio, restart the game. A /reload isn't enough.

  • Api wires everything up.Program.cs calls AddApplication() and AddInfrastructure().

How a request moves through the layers

Request flow

GET /api/quests/783/audio/accept

  1. Api

    QuestsController calls QuestService.GetOrCreateAudioAsync(783, Accept).

  2. Application

    Asks IAudioStore whether 783-accept.mp3 exists. If yes, it returns the file and stops here.

  3. Application

    Loads the quest through IQuestRepository and takes its accept text.

  4. Domain

    TextCleaner replaces $N, $B, $G and the other placeholders.

  5. Infrastructure

    AzureSpeechSynthesizer calls Azure Speech and gets MP3 audio back.

  6. Infrastructure

    FileAudioStore saves 783-accept.mp3 in the addon's audio folder.

  7. Api

    The controller returns the audio as audio/mpeg, so you can listen in the browser too.

Phase 3Speak any text

Done

POST /api/speech with some text returns an MP3.

Objectives

  • Application
    • the ISpeechSynthesizer interface
    • SpeechService: checks the text isn't blank or over 3,000 characters
    • the SpeechRequest DTO with an optional voice, and two exception types
  • Infrastructure
    • AzureSpeechSynthesizer: the Phase 1 code, now returning MP3 bytes. Uses the default voice when none is given
    • SpeechOptions: key and region from the environment, default voice from appsettings.json. The API won't start without them
  • Api
    • SpeechController, which returns audio/mpeg
    • GlobalExceptionHandler: ProblemDetails with 400 for bad input, 502 when Azure fails
    • WowTts.Api.http with sample requests

Complete when

  • ✓ A request returns an MP3 that plays.
  • ✓ Blank text, missing text or an unknown voice gives 400.
  • ✓ A wrong key gives 502 with Azure's reason.

Phase 5Quest viewer
